# طلبك جاهز — نموذج الإثبات العملي

نموذج يعمل فعلا يحول جوال العميل إلى جهاز نداء دون تطبيق ودون حساب. يحتوي على ثلاث قنوات تنبيه تعمل معا من مسحة QR واحدة.

1. **البث الصوتي الحي** (آيفون وأندرويد، دون أي إذن): بعد لمسة واحدة على زر «نبهني» يسحب الجوال بثا صوتيا صامتا من الخادم، وعند الجاهزية يحقن الخادم نغمة النداء داخل البث نفسه. الجوال لا يحتاج إلى تشغيل أي كود عند الجاهزية، فمشغل الوسائط وحده يشغل ما يصله ولو كانت الشاشة مقفلة.
2. **إشعار المتصفح Web Push** (أندرويد أساسا): يطلب إذن الإشعارات في اللمسة نفسها. إذا قبل العميل يتوقف البث الصوتي تلقائيا لتوفير البطارية.
3. **App Clip** (آيفون، المرحلة الثانية): هيكل الكود في مجلد `appclip` والخادم جاهز لإرسال إشعار APNs متى وُضعت مفاتيح Apple. لم يُبنَ ولم يُختبر هنا.

## التشغيل بنقرتين

على ماك انقر مرتين على `START-mac.command`، وعلى ويندوز انقر مرتين على `START-windows.bat`. يثبت الملف ما يلزم في أول مرة، ثم يفتح لوحة الكاشير في المتصفح تلقائيا برابط عام آمن. إذا لم يكن Node.js مثبتا يفتح لك موقعه لتثبيته ثم تعيد النقر. على ماك قد يظهر تحذير أن الملف من مطور غير معروف، فانقر عليه بالزر الأيمن واختر «فتح».

## النشر على Render بدل اللابتوب

المجلد يحتوي `render.yaml` جاهزا. ارفع المجلد إلى مستودع GitHub، ثم أنشئ في Render خدمة من نوع Blueprint من هذا المستودع واختر الخطة المجانية. سيعطيك رابطا بالشكل `https://talabak-jahiz.onrender.com/cashier`. الخطة المجانية تتوقف بعد 15 دقيقة دون زيارات، وإبقاء لوحة الكاشير مفتوحة يكفي لمنع ذلك أثناء التجربة.

## التشغيل من سطر الأوامر

يحتاج لابتوب عليه Node.js 18 أو أحدث (من nodejs.org، نسخة LTS).

```bash
cd talabak
npm install      # مرة واحدة، يثبت المكتبات وأداة النفق
npm start
```

يفتح `npm start` الخادم ورابطا عاما آمنا مؤقتا عبر Cloudflare دون حساب، ثم يطبع رابط لوحة الكاشير بالشكل `https://xxxx.trycloudflare.com/cashier`. افتحه على اللابتوب واترك نافذة الأوامر مفتوحة. الرابط يتغير في كل تشغيل.

إذا لم يفتح الرابط العام (شبكة شركة تحجبه مثلا) يطبع البرنامج رابطا محليا يصلح لتجربة البث الصوتي فقط إذا كان الجوالان على شبكة الواي فاي نفسها.

لتغيير اسم المقهى الظاهر: `CAFE_NAME="اسم المقهى" npm start` على ماك، أو `set CAFE_NAME=اسم المقهى && npm start` على ويندوز.

## التجربة المطلوبة (هاتفان وجهاز كاشير، نحو ساعة)

1. في لوحة الكاشير اضغط «طلب جديد». يظهر رمز QR للطلب.
2. امسح الرمز بكاميرا الآيفون، واضغط «نبهني عند جاهزية طلبي». يجب أن تسمع نغمة التجربة فورا. كرر ذلك بطلب ثان على جوال أندرويد واقبل الإشعارات.
3. اقفل الشاشتين وضع الجوالين في الجيب أو على طاولة بعيدة.
4. تأكد في لوحة الكاشير أن كل طلب يظهر «الجهاز يسحب البث الصوتي» أو «إشعار متصفح مشترك».
5. انتظر المدة المحددة في الجدول أدناه، ثم اضغط «جاهز».
6. سجل هل رن الجوال، وكم ثانية مرت (تظهر في اللوحة بعد أن يضغط العميل «أنا في الطريق» أو يلمس الإشعار).

| الحالة | الآيفون | الأندرويد |
|---|---|---|
| شاشة مقفلة، انتظار 5 دقائق | | |
| شاشة مقفلة، انتظار 20 دقيقة | | |
| زر الصامت مفعل في الآيفون | | لا ينطبق |
| موسيقى تعمل من تطبيق آخر | | |
| وضع توفير الطاقة | | |
| العميل خرج من المتصفح إلى تطبيق آخر | | |
| شبكة المقهى ثم انتقال إلى بيانات الجوال | | |

لاختبار كل قناة منفردة أضف إلى رابط الطلب `?mode=audio` أو `?mode=push` أو `?mode=both`.

معيار النجاح المقترح أن يرن الجوال المقفل خلال عشر ثوان في 19 محاولة من كل 20 على كل منصة.

## ما تحقق آليا في بيئة التطوير (Chromium دون شاشة)

ثبت أن الخادم يحقن النغمة في البث خلال نحو 40 مللي ثانية من ضغط «جاهز»، وأن الصفحة تشغل البث وتعرض الجاهزية وتسجل زمن استجابة العميل. وقيس زمن الوصول المسموع من ضغط «جاهز» حتى خروج النغمة من مشغل الصفحة فكان بين 4.8 و5.3 ثانية بمعدل بث 64 كيلوبت في الثانية. لم يُختبر سلوك آيفون أو أندرويد حقيقيين عند قفل الشاشة، ولم تُختبر إشعارات المتصفح لأن بيئة التطوير لا تصل إلى خوادم الإشعارات. هذا بالضبط ما تقيسه التجربة أعلاه.

اختبارات الخادم موجودة في مجلد `test` وتعمل بعد تشغيل الخادم على المنفذ 3999.

## تكامل Foodics

نقطة الاستقبال `POST /webhooks/foodics` هيكل مبدئي ينشئ الطلب ويعلن جاهزيته عند وصول حالة منتهية. أسماء الحقول تحتاج مطابقة مع وثائق Foodics الرسمية وحساب مطور فيها قبل التشغيل.

## قيود معروفة في النموذج

البيانات في الذاكرة وتضيع عند إعادة التشغيل. واجهة `/api/orders` مفتوحة دون حماية وتعرض كل الطلبات، وهذا مقبول للتجربة فقط.
